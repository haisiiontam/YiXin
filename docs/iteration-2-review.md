# 弈·信迭代 2：验收与课程报告补充

日期：2026-10-28。此文是原课程报告的迭代补充，原 Word/PDF/PPT 未自动重写。源码根目录 `E:\Gomoku\app`。先期过程与失败保留在 Git、worklog 和 bug-retrospective 中，最终结果以本页及最新原始 JSON 为准。

## 1. 为什么这样改

原版已有真实状态通道与合约验证，但需要第二个浏览器才能体验，落完棋也缺少继续探索的入口。迭代选择“一个人可以完整演示，一盘棋可以回看，一份结果可以核验并留念”。新增功能沿用完整棋谱双签，保留原合约与拒签救济路径。

| 改进 | 用户价值 | 软件工程证据 |
| --- | --- | --- |
| 三档 AI，黑白可选 | 单人即可体验完整开通、签名与结算 | 第二本地钱包，每手双签；恢复前核验链上身份和回执 |
| 时间轴、自动播放、曲线、点评 | 解释胜负过程，展示分析能力 | 只读展示状态，不改变签名/积分，不发交易 |
| 威胁点与落子建议 | 看出防守和进攻的理由 | 与共享规则/分析器交叉检查，曲线注明非胜率 |
| SVG 对局证书 | 答辩可展示，棋谱可保存 | 生成前验证非空谱双签；元数据与链上核验边界明确 |
| 宣纸、墨、朱砂双主题 | 统一视觉语言和界面层级 | 设计令牌、响应式样式、字号/对比度审计、真实截图 |
| 持久化与到期取消 | 初始化失败或刷新也可恢复 | 先保存钱包再发锁分交易；27 项客户端专项回归 |

AI、棋型分析、证书版式与合成音效为本项目新增代码；React、ethers、Ganache 等第三方模块沿用锁定版本及许可证声明。AI 采用棋型启发式、搜索和连续冲四策略，不宣称训练模型或职业棋力。

## 4. 推荐的 8 分钟答辩顺序

1. **0:00–0:45，问题与价值**：普通五子棋的对局结果由单方服务器决定，本项目用双方签名与合约重放提供可核验结果；本地教学系统，无现实资产。
2. **0:45–1:30，雅致界面与单人入口**：展示日/夜主题，选择AI难度与执子，说明AI也是第二个钱包。
3. **1:30–2:30，稳定完成一局**：演示现场优先用“运行完整自动演示”，它固定9手，更适合控时。人机对弈另用已有截图或短操作展示，不承诺现场限时赢棋。
4. **2:30–3:30，实验室**：指出每手双签而无单步交易，open/join/settle三笔；复制真实hash，区分初始化与每局交易。
5. **3:30–4:30，复盘**：回到终局前一手、标出威胁点、展示评分曲线与点评。强调复盘只读，评分不是胜率。
6. **4:30–5:15，证书与证据**：从历史导出SVG，说明签名核验与链上结算核验有不同边界。
7. **5:15–6:30，异常与修复**：用真实拒签E2E截图说明8手快照挑战、强制落子；讲一个恢复身份缺陷和手机布局缺陷的修复。
8. **6:30–8:00，工程过程**：展示需求→ADR→代码→测试→Git的链条、81项自动测试与18组浏览器测试；最后说明真人试用尚未完成和主线程搜索局限。

## 5. 报告里最适合展开的 Bug

- **恢复证据不能只验签**：有效签名可能来自别的通道。补齐链、合约、通道、参与者、角色、积分与回执的交叉核验，拒绝分支用真实签名测试夹具覆盖。
- **先持久化再发交易**：open成功但join失败会产生部分锁分。将AI钱包与证据写入提前到第一笔交易前，刷新可恢复待加入状态，到期取消可退款。
- **自动检查与截图目测互补**：手机布局虽无横向溢出，却把导航竖排且挤断品牌；新增导航/品牌高度断言并修CSS。对比度审计发现12项问题后调整色彩令牌。
- **不要把未签名元数据说成核验结论**：证书移除不可信的节省比例，交易和积分标为文件自述，保留独立RPC验证路径。

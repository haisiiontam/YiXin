# 弈信软件工程严格评审与改进结果

日期：2026-11-05。评审基线：Git `12b4235`。本轮由开发辅助 AI 阅读、检查、实现和自动验证；新增代码与模块设计按用户明确指定计入谭海翔的分工。此文是内部工程评审，不是教师评分、多人评审或独立安全认证。

## 总体判断

项目已经具有完整谱规则、真实签名、可执行合约、对抗回归和较清楚的信任边界。严格看，它更成熟的部分是“协议验证实验”，薄弱处是“普通人遇到异常后能否保住成果并继续”。功能多、文件分层和测试总数都不能单独证明这一点。尤其是，退出机制要求保存双签，而保存失败时原界面没有同等强度的行为约束，说明架构的关键不变量尚未贯穿用户流程。

若目标仅是让同学玩五子棋，中心化记分明显更便宜。状态通道的课程价值在于学习授权、状态机、失败恢复和验证；单节点操作者仍可重置链，不能把少交易推广成现实信任问题的通用解法。改进应优先缩短失败后的恢复路径，而不是继续堆叠玩法或链上功能。

## 采用的原则及资料

以下是对原始教学资料的概括及本项目的工程推断，不是大学对本项目的评审意见。

- [MIT 6.102 Designing Specifications](https://web.mit.edu/6.102/www/sp26/classes/05-designing-specs/)：接口应说明异常后的状态；模糊的部分变更使调用者无法恢复。应用到本项目：把“写失败后还能拿到什么、还能否继续签名”写成约束。
- [MIT 6.102 Testing](https://web.mit.edu/6.102/www/sp25/classes/02-testing/)：按输入分区和边界设计小而有效的测试集。应用到本项目：配额/拒绝/损坏分开测，举证与响应期限测等号两侧，保留修复前失败。
- [MIT HCI Heuristic Evaluation](https://designftw.csail.mit.edu/lectures/heuristic-eval/)：状态可见、错误预防、恢复指导和效率。应用到本项目：给用户显示“现在处于哪一步”，在签名前确认坐标，并提供键盘快捷路径。
- [Stanford CS147 2025 个人启发式评估作业](https://hci.stanford.edu/courses/cs147/2025/au/assignments/Assignment_07_Heuristic_Evaluation_Individual.pdf)：评估已实现交互、记录具体问题与严重度，并区分启发式评估与真实用户测试。应用到本项目：逐个反例定位，避免用“再加几个功能”代替质量评审。

Parnas 的信息隐藏沿用项目已有文献：按易变决策划分模块。本轮落实为存储表示与恢复建议两个独立边界；其原论文书目信息可由 [CMU 馆藏](https://doi.org/10.1184/r1/6607958)定位。该馆藏全文接口本次返回 403，不冒称从它读到了全文；核心判断同时由上述 MIT 规格资料和实际代码支持。

## 缺陷、优先级与处理

本表 P0/P1/P2 是工程排序，不是 Stanford 的 0–4 量表，也不代表课程分数。

| 问题 | 为什么严重 | 本轮处理及可核验入口 |
| --- | --- | --- |
| P0 双签保存失败后仍可继续签名 | 没有最新证据就不能兑现链上退出保证；继续签名扩大未持久化损失 | GameRepository 写后核对；内存留存、暂停后续签名、下载与重试；真实浏览器配额故障已走完恢复结算 |
| P1 连接先成功后验证，认证前断线悬空，迟到签名发往旧连接 | 成功契约不真实，失败无终态，异步任务越过会话边界 | 首次房间安装后兑现；错误/关闭/取消/超时均结束等待；socket＋wallet 身份检查；修复前后回归 |
| P1 同一待确认广播重复弹钱包 | 重复副作用使用户无法区分新授权与重试；外部验收实际观察到签名次数多一次 | ACK 幂等；自动重复不签，手动重发复用原签；保留外部首次失败和额外红测 |
| P1 恢复步骤分散，用户必须记住协议术语 | “能退出”不等于“用户能正确退出”；终局棋谱、结算积分、过期提案容易混淆 | 纯策略恢复助手；保存/双签/交易清单分开；节点时间未知时不猜期限；原房间重连保留进度 |
| P2 225 个按钮缺少高效键盘访问，误触后无授权前撤销 | 原生按钮数量不能证明无障碍；事后悔棋又与双签规则冲突 | 单 Tab 网格＋方向键＋逐点描述；触屏默认确认；强制落子始终确认；Escape 取消且不发提案 |
| P1 验证与确认混用、公开交付口径漂移 | 自动脚本不能证明真实用户学会恢复；当前 GitHub 仓库为 private，不能称公众已可获取 | 更新 V4 和交接资料的表述；保留真人任务、读屏器、插件钱包与公开课程页面的未完成状态 |
| P2 控制器职责仍集中，正式报告与旧 ZIP 会滞后 | 文档自称模块化不等于变更被隔离；交付可能拿错版本 | 提取存储与纯策略，增加 ADR 和追踪；V4 为当前答辩入口，旧正式报告/ZIP明确是历史材料，未重新打包 |

## 可观察的改变

1. **证据保存有契约。** 存储错误现在是可见状态，不再依赖日志猜测。已经得到的新双签仍可下载，原磁盘旧记录不会被清空。磁盘写入失败后不继续授权下一手。历史索引失败单独报告，不伪装整局丢失。
2. **原房间可以续接。** 断线后点击“重连原房间”，核验已有进度后继续；自动确认关闭，需要用户看清待确认提案。重连本身只认证和读取，不重新锁分。重复 ACK 不增加钱包提示，显式重试保留原授权。
3. **安心助手解释下一步。** 未保存、钱包失效、中继断线、待确认、举证、响应、超时、待结算与已结算各有解释。策略不拥有签名或交易能力，避免“助手建议”等同“自动授权”。
4. **授权前允许反悔。** 坐标对话框取消不会签名或发送提案；确认前校验局面版本。已双签谱继续不可改。触屏默认开启确认；桌面可自行选择。网格只占一个 Tab，方向键还能检查已落子。

## 验证与证据边界

最终数据由 `scripts/summarize-recovery.mjs` 从 `final-after-ack/` 原始结果逐份重算，见 [本轮汇总](../artifacts/test-results/recovery-2026-11-05/review-summary.json)。保留最初 4 个缺陷的失败记录、重复 ACK 的额外失败记录，以及外部钱包首次 3 过 1 败的中间记录。没有删掉失败来制造全绿。

新增浏览器验收用两个独立浏览器钱包，在真实本地 EVM 上走完：零手磁盘旧证据→第一手双签但配额失败→下载并独立验签→保存重试→两手断线→原房间重连→关闭自动确认后的手动签名→九手三笔结算。另验证触屏 390 像素默认确认、键盘只读访问、对话框取消、日夜主题及减弱动效。脚本是自动装置，不是用户访谈或真人满意度证据。

仍未完成：真实新手能否不看说明完成恢复、真实读屏器体验、真人插件钱包批准流程、长时并发/恶意同源脚本场景、公开课程获取页与保留期。没有据此部署公网、修改仓库可见性或制造反馈。

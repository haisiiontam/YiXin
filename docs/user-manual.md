# 弈·信用户使用说明

## 2026-11-05 新增操作

- **对局安心助手**在已有对局时显示保存、双签和节点交易清单，按当前异常给出下一步。终局棋谱不等于积分已到账；仍需结算回执。它不自动签名或发交易。
- **存储失败**时保持页面打开，先点“备份本局证据”。磁盘可能仍是旧棋谱，而当前页面保留了更新双签。恢复浏览器存储空间/权限后点“重试本地保存”；保存失败期间暂停新签名。若人机回合因此暂停，保存后可点“继续 AI 回合”。不要直接刷新或清除浏览器数据。
- **中继断开**时可点“重连原房间”，保留原进度并核验；重连关闭自动确认，待确认提案需要手动检查。若中继无法恢复但RPC仍可用，打开异常实验进行争议。整台本地服务停机时，需要先恢复服务。
- **键盘棋盘**只占一个Tab入口；方向键移动，Home/End到行首尾，Ctrl+Home/End到全盘首尾，Enter或空格选择合法空点。可逐点听取/读取已有棋子的坐标与手数，不能绕过轮次和禁用保护。
- **落子前确认坐标**桌面可选、触屏默认开启；链上强制落子始终确认。Escape或“返回棋盘”在签名前取消，不发送提案；确认后仍须按协议等待共同确认。已经双签的棋谱不可悔棋。
- 启用系统“减弱动态效果”偏好会减少棋子和胜线动画。本轮已做自动浏览器检查，真实读屏器体验仍待人工确认。

适用版本：课程本地教学版本。积分只用于演示，不可兑现。本文步骤对应最终中文界面。

## 1. 启动与检查

1. 工作区固定E:\Gomoku；双击根目录“启动游戏.cmd”。首次在新环境使用时先按README安装工作区依赖。
2. 打开http://127.0.0.1:4173。已运行服务时直接使用现有窗口；启动器保持开启，Ctrl+C停止。
3. 顶部应显示本地EVM已连接、链ID31337和钱包地址。网络错误时不要把未发送交易当成功，先检查启动窗口。

## 2. 一分钟快速演示

点击“运行完整自动演示”。系统明确使用两个独立本地测试钱包，实际注册、锁分、完成9手黑胜并结算。结束后打开“通道实验室”，查看本局3笔真实交易、gas与11笔逐步上链公式对照。该功能是脚本演示，不是AI棋手或真人用户。

## 3. 双人对局

1. 玩家A使用普通浏览器创建对局，选择每人锁定积分，默认10。第一次使用自动执行一次注册，领取1000演示分并获得本地测试gas。
2. 创建者复制邀请链接，交给玩家B。B在**不同浏览器/独立配置/无痕上下文**打开。A和B在同profile两个普通标签会共享钱包，不能代表两方。
3. B填写或从链接获取邀请码并加入，确认双方地址与锁定积分。黑方open和白方join分别上链，双方开通完成后才可落子。
4. 黑先白后，在空交叉点落子。当前方签完整棋谱，对方自动验证并确认后才提交为已确认棋子。未确认提案显示等待，不改变已确认轮次。
5. 横、竖或斜连续至少5子获胜，满盘无胜为和棋；无禁手。重复位置、错误轮次、终局后走棋会被拒绝。
6. 终局点击“链上结算本局”。等真实回执后积分改变：双方原1000、各锁10时，胜方1010、负方990。正常一局为open+join+settle三笔，注册/部署不计入这三笔但有独立成本。

## 4. 拒签与链上继续

展开“签名与异常实验”，关闭“自动确认对手提案”可做受控拒签实验。棋手保留最近完整双签快照，点击“提交最新快照挑战”。

在“链上争议中”，本人轮次可开启“棋盘使用链上强制落子”并点击棋盘，直接由合约校验。每次有效非终局推进都会为下一方重置完整响应期；形成胜局则立即结算。对手拒签最后胜手时，可提交前8手双签后本人forceMove第9手，实测4笔对局事务可结算。

倒计时到期，成员可点击“领取超时结算”，当前应该落子却未行动的一方判负。期限以链上时间为准；边界严格为响应时t<deadline、超时t>=deadline。请在争议期保持监控，首版没有守望服务，不保证永久离线安全。

## 5. 邀请到期

未有人加入时，黑方锁分不会立即消失。邀请期到达后，黑方可执行界面的邀请取消操作，链上退款。相同channelId不可复用，重新开局需新salt/邀请。

## 6. 导出、导入与恢复

对局中或结算后点击“导出证据 JSON”。文件包含链、合约、参与方、锁分、棋谱、双方签名、摘要与回执索引，**不含私钥**。

另一浏览器展开实验区，选择“导入证据 JSON”。软件先检查格式、完整谱、签名域和双方签名，再用本地RPC核对实际参与者、stake及每笔回执。非本局玩家只能查看，不能获得挑战、超时或结算权限。篡改包应出现错误，不能以文件中的winner直接决定积分。

正常刷新会恢复持久化证据并核对链；中继不可用而RPC仍可用时可以手动导入后直接链上操作。整个本地服务停止时RPC也不可用，须先恢复服务；离线只能用CLI核验签名，不能声称链上已结算。

浏览器测试钱包保存在本机该profile的localStorage，证据文件不能恢复私钥。清空浏览器数据前保存证据和正确的测试钱包配置；禁止导入真实资产私钥。

## 7. 数据解释与常见问题

- 实验室m+2是同规则逐步上链对照公式；进行中显示当前快照，不能视为最终节省。合约测试另有9/10手完整局真实基线，不混为浏览器当前局的逐笔实测。
- gasUsed是执行成本单位，不是交易笔数、TPS或真实付款。争议会增加事务数。
- “不能与自己开局”：切换独立浏览器上下文，别使用同profile普通标签。
- “无最新双签”：拒签的提案没有双方授权，应使用上一完整双签；初始空谱可进入争议。
- “证据回执不存在”：确认使用原链实例。源码包不带原数据库，重建链后旧回执不在新链，须重新对局/测试。
- “余额仍是990”：这是锁分后可用余额；未结算之前不得把锁定stake重复算入可用积分。
- “uWS binary missing”：Ganache可回退JavaScript实现；以实际服务启动和测试结果判断运行，不能据此当安全故障或公网性能结论。

## 8. 停止、备份与再次启动

关闭服务前建议导出重要快照。Ctrl+C停止，重启同一工作区会读取artifacts/runtime持久链与房间。不要随意删除运行时目录；重建链时使用新的随机salt并隔离旧证据。开发节点只绑定127.0.0.1，不直接公开该RPC。


## 房间取消与主动结束 2026-11-07

未匹配房间由房主点击“取消房间 / 邀请”，等待服务器确认后原邀请码失效。待接受的链上邀请可由黑方立即取消并退回锁分。双方已经开局或进入争议后，使用“认输并结束本局”，确认会判对方获胜并结算；可选择“继续对局”撤回确认。结束后点击“返回大厅”再创建或加入新局，证据历史保留。关闭浏览器、断开中继或返回界面本身不会完成链上退出。

# 2026-11-10 缺陷核查与开发过程补记

本记录以用户本轮复查意见为输入，对照实际仓库逐项核实。核查前版本为 `a453e73420bf5bb7aa2a6a9f80ae738de9008183`。区分“用户报告的历史问题”“当前代码已具备机制”“本轮修复”“尚未实现的改进”；静态检查不冒称新机器实测，历史通过不冒称本轮重跑。原始历史记录保留在[缺陷复盘](bug-retrospective.md)、[可信核验](trust-audit-2026-11-04.md)、[恢复评审](engineering-review-2026-11-05.md)和[退出 ADR](adr-lifecycle-20261107.md)。

## P0 交付与可移植性

### D01 固定项目根目录导致迁移即退出

- 来源与现象：用户报告旧版 `start.ps1` 要求根目录必须为 `E:\Gomoku`，移至桌面即抛异常。这是环境依赖泄漏，不是业务约束。
- 核查：本轮读取时该守卫已不存在；脚本已由 `$PSScriptRoot` 推导项目根。按用户报告记录历史，不能冒称本轮重现或由本轮首次修复。
- 验收：从不同名称、含空格的目录启动，日志、缓存和运行目录落在对应项目内；不依赖原盘符或用户名。仅复制源码不能凭空获得 Node 和依赖。

### D02 个人 Node 路径与缓存路径残留

- 来源与核查：用户提到 Lenovo 路径及 `.npmrc` 的 `E:/Gomoku/.cache`。当前 `.npmrc` 已无固定 store/cache；`start.ps1` 和已存在的 `bootstrap.ps1` 却仍有另一用户名的绝对 Node 备用路径。
- 本轮修复：移除个人路径，统一使用 `NODE_BINARY` 或 PATH；TEMP、npm 缓存、pnpm store、包管理工具下载目录由脚本位置推导。链运行时的两条错误提示也改为显示实际工作区。
- 边界：历史日志中的原始命令保留，以免篡改过程；旧图表、课程材料提取与打包辅助脚本仍含原环境路径，不能据此承诺所有开发工具均可迁移。本轮修正面向交付启动入口和当前 README、外部链指南。

### D03 缺依赖仅报错与 bootstrap 越界安装

- 核查：bootstrap 已存在，不能记成“从无到有”；但 start 仅提示手动执行，bootstrap 缺 pnpm 时会 `npm install -g pnpm@latest`，依赖未固定且会写全局目录。此前版本判断还会放过 Vite 7 不支持的 Node 21 和早期 22。
- 本轮修复：start 调用 bootstrap；缺 Node 给出官方下载地址，检查 Node 20.19.x 或至少 22.12；缺依赖通过 `npm exec --package=pnpm@10.11.0` 使用固定工具，`--frozen-lockfile --ignore-scripts` 安装，工具与依赖缓存均在项目内，不安装全局包；缺前端产物时构建。增加 `-CheckOnly`，只检查不下载。
- 验证口径：本轮实际命令、退出码和迁移烟测见 `artifacts/test-results/portability-20261110/`。实测缺 Node 官方提示、小型全新依赖安装夹具（固定 pnpm 实际下载、冻结锁文件、安装一项依赖）、含中文与空格目录内的真实产品启动和 HTTP 健康检查通过；运行时回归 13/13 通过。迁移烟测共享已有依赖，新安装夹具不是完整产品安装，也没有据此宣称第二台机器或浏览器 E2E 已验收。
- 本轮首次自检确实失败：PATH 同时存在两份 Node 时，Windows PowerShell 的 Get-Command 返回多个 Application，误把两条路径当成一个可执行命令。改为明确选择首个匹配；原始错误保留为 `bootstrap-check-first-failure.txt`，后续结果分文件记录。

### D04 声称无 Git 与伪造开发历史的风险

- 核查：`E:\Gomoku\app` 已是 Git 仓库，实际存在 `f73ef51`、`30dbfbb`、`5510395`、`12b4235`、`ad13378`、`a453e73` 等提交。“没有 .git”不适用于当前克隆；源码 ZIP 不带 `.git` 也不等于从未版本管理。
- 处理：保留真实提交与日期。旧日志可在今天补记并明确来源，不拆成几条假装当时完成的历史提交；新修改只能形成当日真实提交。

## P1 协议与安全

### D05 测试币与注册积分缺少身份约束

- 核查：HTTP faucet 提供的是本地链测试币，合约 `register()` 才是每地址一次的 1000 演示积分。两者必须分开统计。HTTP 当前已有地址 10 秒冷却、来源 IP 每小时 120 次新注资限制，状态在内存中，重启后清空。
- 遗留：新建地址仍可重复注册积分，限流不是抗女巫身份机制；同浏览器一次领取也可被清理存储、无痕配置或直接调用绕过。不能把这些措施写成已消除女巫攻击。
- 建议与验收：只在本地教学范围使用；如扩展为有价值积分，应采用服务端一次性邀请码或可验证身份、持久化额度与并发原子计数，并实测重启、并发及多地址绕过。本轮未修改身份模型。

### D06 无离线争议守护

- 核查：目前没有 watchtower。默认挑战参数 60 秒，但协议有完整证据期及后续响应期，二者期限不能混淆；结算需实际链上交易。
- 建议：服务端轮询链上通道，在 `proofDeadline` 和响应 `deadline` 各自到期前提醒已认证房间玩家，重连补读状态，按通道、阶段和期限去重。15 秒提醒阈值要允许短周期测试配置。
- 边界：WebSocket 只提醒在线且已连接的页面，不能替离线玩家提交双签或付 gas；服务器故障也会漏报。自动代举证还涉及最新证据保管、授权、费用与可用性，不是“加一个定时器”就获得离线安全。本轮记为待办，未声称实现。

### D07 重建相同链身份后的旧签名复用

- 核查：域仍是 name、version="1"、chainId、verifyingContract；房间另用随机 salt 派生 channelId。同 chainId、同合约地址且重建同一通道身份和可接受状态时，旧签名有条件复用的风险存在；不能写成“任意新房间均可复用”。随机房间 salt 降低意外碰撞，部署 manifest 拒绝误接旧链，但不提供密码学上的部署代次绑定。
- 待办：把部署随机标识绑定到签名结构或通道身份，贯通合约、客户端、独立证据核验、manifest 与迁移测试。应增加同 ID/同地址重建的红测，再验证旧证据被拒绝。
- 更正：本项目锁定的 OpenZeppelin 5.4.0 `EIP712` 构造函数只有 name/version，不能直接加第三个 salt 参数作为一行修复。`eip712Domain()` 返回 salt 字段不意味着当前分隔符包含它。参考[锁定版本源码](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/v5.4.0/contracts/utils/cryptography/EIP712.sol)与 [EIP-712](https://eips.ethereum.org/EIPS/eip-712)。本轮未更改签名协议。

### D08 RPC 开发管理接口暴露的复查

- 核查：当前 `server/chain-runtime.mjs` 已有显式 `RPC_ALLOWLIST`，HTTP 单项和批量均经 `runtime.rpcRequest`；未列方法拒绝，外部模式禁 faucet。`evm_setAccountBalance` 仅供本地内部注资使用。
- 状态：当前版本已防护，已有历史运行时测试；不是本轮新增修复。不采用“只排除 evm_/personal_/debug_ 其余都放行”的黑名单，因为仍可能漏掉其他管理方法。
- 回归要求：保留单项与批量管理方法拒绝、外部 faucet 403、客户端已签原始交易广播等测试；白名单变更须逐项审查能力。

## P2 工程与体验

### D09 ethers 首屏加载与分包边界

- 核查：当前构建已有独立 `evm` 包约 332584 字节，但 App 静态导入 ChannelClient，后者静态导入 ethers，独立分包不等于按需加载。用户给出的 gzip 数字属于复查输入，本轮未重新测量传输压缩量。
- 待办：延迟初始化钱包/会话及相应 import，给出加载、重试和禁操作反馈；不能仅改一个 import 而让所有同步调用失效。验收应记录初始请求与进入对局后的请求，比较冷缓存体积及可交互时间，并回归恢复和退出。

### D10 浏览器测试依赖 Edge

- 核查：多份 E2E 脚本默认系统 Edge 固定安装位置，支持 `BROWSER_PATH` 覆盖。只安装 Playwright Chromium 不会自动替换该显式路径。
- 本轮处理：README 明确现有前提及覆盖方法；尚未将各脚本统一为自动发现浏览器。后续可抽取启动器，依次选择显式路径、工作区 Chromium 与已安装 Edge，浏览器下载及配置保持工作区内。

### D11 测试耗时与 fixture 复用

- 核查：`tests/contract.test.mjs` 已在 before/after 共享 Ganache provider；多个测试文件各有隔离链，具体场景仍可能部署新合约。不能把“每个用例都重启 Ganache”直接写成当前事实。
- 待办：先按各测试文件统计启动、编译、部署及轮询耗时，再考虑编译结果复用与 snapshot/revert。复用不能破坏时间推进、余额、nonce 和事件隔离。用户提到 76 秒为其观察，本轮未复测此计时，不承诺减半。

### D12 服务端职责集中

- 核查：`server/index.mjs` 集中 HTTP 路由、房间认证与中继、faucet 和静态服务，链 runtime 已独立。本轮文件长度与“161 行”的旧观察不同。
- 待办：按 RPC 适配、房间领域/持久化、测试币服务拆分，由装配入口注入 runtime 和仓储；先固定接口与取消后的旧邀请拒绝等回归。模块名称数量不是解耦证据，应检查能否独立测试、是否共享隐式全局状态。本轮未执行该重构。

### D13 房间持久化与崩溃恢复

- 核查：当前 saveQueue 内已经采用同目录临时文件 writeFile 后 rename，串行队列与原子替换可以并存，不是互斥方案。
- 遗留：尚无 fsync 与真实断电验收，不能承诺断电后最后一次更新绝不丢失。读取 rooms.json 的通用 catch 还可能把损坏文件当成空房间，应区分不存在、格式损坏与权限错误，并提供只读恢复或明确失败。
- 验收：加入写入失败、替换失败、遗留临时文件及损坏 JSON 的故障注入；确认不会静默丢失有效房间或把已取消邀请恢复为可加入。本轮没有声称完成这些新故障测试。

### D14 无障碍与误触

- 核查：棋盘已有 grid/row/gridcell、单 Tab 焦点、方向键、Home/End、Enter/空格、坐标与棋子描述；强制落子有确认。不能以 aria/role 出现次数判断是否可访问。
- 历史缺陷：此前 225 个按钮不便键盘巡检、触屏误触没有授权前撤回，已在 11 月 5 日迭代修复并留浏览器证据。
- 遗留：真实读屏器、仅键盘完成全任务和不同缩放情形仍需真人验收，不能用自动化通过替代。

## 生命周期遗漏与其他真实失败

### D15 创建房间后无法取消以及中途无法退出

- 来源：用户实际反馈，属于用例遗漏：只写开始和获胜，没有取消、替代流及主动结束的后置条件。
- 11 月 7 日修复：未匹配房间由房主取消并持久化失效标记；待加入链上邀请黑方可立即退款；Active/Dispute 中成员可认输，二次确认后对方获胜；终态返回大厅清理当前邀请参数、保留历史证据。关闭页面不会自动结算积分。
- 真实失败：首轮 164 过、2 败，新增重复操作断言只等交易提交，没有等实际回滚回执。修正等待回执后 166 项全通过，另有 8 组旧浏览器回归和 4 组新生命周期场景。父目录保留初轮失败，final 保留最终结果，不能仅展示全绿摘要。

### D16 证据持久化和会话竞态

- 历史事实：双签保存配额失败后仍可继续授权；连接成功早于房间安装；认证前断线导致等待悬空；迟到回调越过会话；重复 ACK 多次弹签名。
- 已有修复：GameRepository 写后核对并显式返回失败，内存保留可下载证据、暂停后续签名；连接代次及 socket/wallet 身份核验；ACK 幂等，手动重发复用签名。修复前后结果和外部首次 3 过 1 败均保留，详见恢复评审。

### D17 旧快照攻击和证据统计失真

- 历史事实：旧快照后立即强制分叉可阻挡更新的合法终局；宽松域/签名与合约不一致；导入覆盖较新双签；证据文件自报 gas/漏交易影响统计；旧八字段 ABI 被误读为九字段；异步切链可能混入旧连接结果。
- 已有修复：证据期与响应期分开、完整前缀检查、严格域和签名、可信 RPC 回执重建、部署与空通道布局探测、连接代次保护。T1–T7 逐项证据见可信核验报告。没有扩展成“所有安全风险已消除”的结论。

### D18 界面、AI 与测试工具自身的错误

- 保留历史：重构误删空交易提示；AI `budgetMs/timeBudgetMs` 字段不一致；浅色/深色对比度失败与 11px 小字；刷新后找不到证书入口；AI 恢复被旧房间书签抢占；钱包在锁分后才保存造成失败恢复困难；评估曲线被误写成胜率；证书元数据未经 RPC 却像已验证。
- 工具与断言错误另记：测试停在错误页面、4190 受限端口、脚本语法错误、和棋夹具奇偶写反，以及 AI 小样本验收阈值调整和曾误述中间结果。它们能解释过程，但不能全部包装为产品缺陷，也不能隐藏阈值变化。原复盘保留当时数据与局限。

### D19 持久化链身份与清库的取舍

- 默认运行目录会保存链数据库、deployment manifest 与 rooms.json，便于重启续接；manifest 对代码、周期、链指纹等漂移拒绝复用。合约变化时选新目录，保留旧数据，不能通过删库冒称迁移。
- 同身份重建的签名风险见 D07；密钥被用户彻底清除后，证据文件也不能恢复身份。迁移验收必须同时检查代码、数据、协议与用户退出路径。

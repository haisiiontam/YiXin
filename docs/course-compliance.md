## 4. 单人+AI实施的真实表述

课程原始要求以最多4人的小组实施，真实身份信息由学生填写。S7图书馆范文PDF第8页明确“本项目小组成员只有我一人”，第44页说明仅一个贡献者，第59–62页为个人工作总结与体会，提供了如实呈现单人项目的参考。当前项目按用户指示由一名学生一体化实施；“单人+AI”是本项目工作安排，参考范文不能证明本项目已获教师批准，也不能将AI列为同学。

- 负责人承担产品、需求、设计、开发、验证、发布准备与文档责任；这些是同一人的工作角色，不是虚构成员。
- AI可分别充当需求辅助、实现辅助、测试建议、审查辅助；必须标注工具身份，不能填入“同组成员/学号”、伪造同学照片、会议发言或人类工时。
- “头脑风暴会议”改为真实个人选题记录与AI讨论摘要，记录真实时间、备选方案、选择理由；有真实教师沟通再另附纪要。没有会议照片就说明“个人实施，无小组会议照片”。
- 将全部WBS任务责任人记为“本人”，AI辅助项独立列示。原教案“每人5–10个任务”是小组粒度建议，单人项目不虚构四人分摊。
- 体会仅写本人实际负责工作中的失败、取舍和解决证据。不能写成多位组员感想，也不能把AI自述当学生经历。
- 过程提交应来自实际时间与实际变更；不得回填伪造历史提交、采访日期、发布日期或团队站会。

## 5. 选题与安全可信交付门槛

S5选题3要求“游戏结束时使用区块链正确结算积分，并尽量避免较大事务负担”。因此界面精致与规则可玩只是基础，核心证据须包含：

1. 实际运行的本地EVM节点、真实部署合约、chainId、部署地址、部署交易回执及运行版本；模拟数字不得标为链上余额。
2. Solidity合约管理积分与对局生命周期，积分不可由浏览器/中继任意改写；正常结算与争议超时路径都须执行并验证只结算一次。
3. 每一步链下EIP-712签名绑定链、合约、协议版本、唯一对局、参与方与序号/状态；验签不能代替规则合法性校验。
4. 规则、签名域、状态有效性、更新顺序、挑战期限、超时结果、旧状态保护与公平性局限有明确设计和反例测试。
5. 交易比较分开统计部署/账户准备、正常对局、争议路径；假设基线明确标注估算，实测数据必须附回执。减少交易次数不能直接写成降低相同比例gas或提升TPS。
6. 证据包能关联棋谱、签名、规则、合约、事件与测试条件；链下记录丢失、用户离线、单节点被控制、双方串谋等信任边界须公开说明。
7. 仅本地演示积分，不兑现金、不接真实资产。开发节点测试账户与私钥只用于隔离本地环境；私钥、助记词不得进入导出证据、日志或公开页面。

正常路径可以少量开通/结束交易；遭遇争议时允许增加交易，不能为了“2笔交易”牺牲用户退出与纠错能力。具体笔数由最终合约流程与实际回执决定。

## 7. 发布与真实反馈：证据不足就明确缺口

课程要求在最后实验课前提供软件介绍页（截图、使用介绍、准确获取方式），其他同学能够评估；使用其他服务器时首页给出地址；网站至少保留1个月。第七次课要求公开发布、收集反馈，第八次课8分钟展示。这些是课程要求，当前文档不证明已完成。

可行的交付方案是“公开介绍/下载/源码页+可重复启动的本地链完整演示包”。它能让用户在自己设备运行真实链；公开静态页若只能展示棋盘，必须说明链功能需要本地环境，不能声称公网用户已连入本地RPC。该方案是否满足教师的在线试用预期需确认；不能把仅作者可访问的localhost写作公开地址。公开发布、发消息或公网链部署仍须依当前授权执行，不因课程文字自动获得外部操作权限。

反馈计划（目标而非已发生事实）：邀请至少3名自愿真实试用者，覆盖首次接触用户、棋类用户、技术评估者；记录招募方式及知情同意。每人执行“理解规则→开局并落子→查看结算→理解负载对照→导出证据”，至少1人体验争议/恢复演示。样本小、便利抽样需在结论说明，不推导全体用户满意度。

| 反馈记录字段 | 填写规则 |
| --- | --- |
| 匿名编号、实际日期、版本、环境、同意范围 | 不编造身份；不收集不必要个人信息 |
| 任务、完成/阻塞、观察到的操作 | 事实与解释分栏；录屏/照片须先获同意 |
| 原话、问题严重度、建议 | 原话和整理意见区分；保存原始材料索引 |
| 关联需求/缺陷、采纳与否、理由、复测 | 形成反馈→需求变更→验证的闭环 |
| 证据权限与隐私处理 | 对外用匿名摘要；地址/截图按需要脱敏 |

没有真实用户时，报告写“尚未开展真实用户试用，反馈证据缺失”；AI可帮助设计问卷，不能生成填答。没有真实公开地址时写“尚未发布”；计划截图、设计稿、本人双账户演示、合成数据均不能替代上述证据。

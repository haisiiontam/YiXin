# ADR 可靠保存与可解释恢复

日期：2026-11-05。状态：已实施，验收见 `artifacts/test-results/recovery-2026-11-05/review-summary.json`。本轮不改变合约 ABI、签名域或棋局规则。

## 问题与约束

状态通道的退出能力依赖最新双签。旧控制器在发布内存快照后直接写 `localStorage`；配额耗尽会抛错，却不禁止下一次签名。连接在收到首个房间消息时就提前成功，认证前断线又会取消超时器而不结束 Promise。异常恢复分散在多个折叠区，用户需要自行推断哪些棋子已授权、何时可以强制走棋。

严格约束：已核验的最新双签不得因保存失败而从内存消失；保存错误不得显示为成功；损坏记录不得自动删除；重连不得清空原棋谱或补发锁分交易；建议模块不得拥有钱包、RPC 或副作用接口。取消只发生在签名前，已经共同确认的棋谱不可悔棋。

## 决策

1. **存储细节由 GameRepository 隐藏。** `readEvidence`、`saveEvidence`、`readHistory`、`saveHistory` 接受可注入存储端。写后读回核对；缺失、损坏和访问拒绝具有不同结果。证据主记录先写，活动通道索引后写，两者不冒称跨键事务。后者失败仍可按通道编号读取前者，客户端保守显示失败。
2. **控制器负责恢复不变量。** `persistence` 明确记录 saved / failed / unknown。保存失败保留最新内存双签，禁止继续 propose、ack 和人机签名，允许下载与显式重试；AI 回合若因此暂停，由用户保存后点击继续。历史索引失败与证据保存分开报告，损坏历史原文不被覆盖。
3. **连接具有明确生命周期。** 认证、房间验证和安装完成后才兑现连接 Promise；关闭、错误、超时与取消均结束等待。钱包引用和 socket 身份同时限定回调；迟到认证签名和旧队列任务不能交给新连接。`reconnectRelay` 保留同一房间与快照，核对前缀，并关闭自动确认及自动开通。
4. **重复提案确认保持幂等。** 同一 channel + signer + 有序棋谱只请求一次签名。自动重复广播不再触发钱包提示；用户显式重发复用已签原文。日志只报告“确认签名已发送”，不提前宣称双方已经共同确认。
5. **恢复建议为纯函数。** `recoveryGuide(snapshot)` 输出阶段、解释和两步建议；其输入不包含钱包或网络客户端。争议分期只读 `chainNow`，不读宿主时钟；节点样本缺失或刷新失败时不猜测阶段。React 助手仅将建议映射为用户主动触发的既有操作。
6. **误触在授权前消除。** 桌面可选、触屏默认开启坐标确认；链上强制落子始终确认。原生 modal 对话框支持 Escape 和焦点恢复；提交前再次检查通道、棋谱、轮次与状态。棋盘采用单一 Tab 入口、方向键、行首尾、只读逐点描述；禁用单元仍由网格读取，保留原生按钮禁用保护。

## 取舍与未解决问题

- 使用现有 Web Storage，避免课程工程为此引入数据库迁移。它不是可靠磁盘承诺，也不抵抗浏览器数据清理、同源 XSS 或恶意扩展。失败期间若关闭页面而未下载，最新内存证据仍可能丢失；故助手明确要求保持页面打开并备份。
- 私钥和 AI 恢复凭据仍属于既有本地教学钱包机制，本轮存储仓库只接管证据和历史索引；外部模式继续由注入钱包保管密钥。
- 不做无人值守自动重连与自动交易，以免重连触发用户未检查的提案或锁分。WebSocket 仍在会话控制器中，尚未完成所有钱包、链事务和中继适配器的进一步拆分。
- 不增加“已确认悔棋”、竞技积分排行或链上聊天。它们会分别破坏签名不可变语义、夸大同控制者积分的可信度、增加无助于核心需求的交易。
- 键盘、触屏、减弱动效已有自动浏览器验证；真实屏幕阅读器、真实用户任务完成率与真实钱包插件仍待人工验收。

## 课程原则与验收入口

契约与异常后置条件：写失败后仍能导出原内存快照。信息隐藏与依赖倒置：存储替身可注入。状态建模：期限等号、未知节点时间、终局与结算分别建模。人本设计：状态可见、错误预防、识别代替记忆。测试依据与出处见 [严格评审](engineering-review-2026-11-05.md)。对应 FR-32 至 FR-35、AT-13 至 AT-16，见需求增补。

# 迭代 2 架构决策记录

接续 `architecture.md` 中的 ADR-001 至 ADR-003。

## ADR-004：AI 对手是第二个本地钱包，而不是协议里的“特殊玩家”

**背景**：需要单人也能完整体验对局。

**备选**
1. 新增合约接口或服务端“机器人房间”。需要改合约，会使 11 组合约测试与已写入报告的数据失效。
2. 客户端直接改棋盘，不签名。会让人机局不产生可验证证据，与项目卖点冲突。
3. **AI 是浏览器里临时生成的第二个钱包，每手与人类各对完整棋谱做 EIP-712 签名。**

**决定**：选 3。

**理由**：合约、中继、证据格式、证据校验器保持兼容；人机局同样是 open + join + settle 共 3 笔交易，可导出可验证证据。最终 Docker E2E 实测23手人机局为3笔，gas分别148797、45697、446417，详见 iteration-2-review。开通前先持久化AI密钥与初始证据，部分失败可恢复待加入状态并到期取消；恢复前核对链、合约、通道、钱包身份、积分及交易回执，临时RPC失败不删除唯一密钥。

**代价与边界**：AI 私钥只存在本机浏览器，证明的是“人与一个本地程序达成的棋谱”，不证明对手是谁。人机局积分同样是演示积分。中继不参与，所以不具备断线续传的服务端状态，刷新后靠本地证据重新核验恢复（`_resumeAi`）。

## ADR-005：分析器与 AI 做成无 DOM 的共享纯函数

**决定**：`shared/analysis.mjs` 与 `shared/ai.mjs` 只依赖 `shared/gomoku.mjs`，不引用浏览器 API。

**理由**：复盘曲线、威胁标记、提示、AI 落子共用一套棋型识别，避免出现“提示说是活三、AI 却不认”；可以在 Node 里做 24 局自博弈与计时，不需要浏览器。**代价**：搜索在主线程执行，最高难度使用约 1000 ms 搜索预算，并在搜索节点中检查时间。预算不是实时系统保证，分析准备与设备差异可能带来超时；弱设备短暂阻塞仍可能发生，后续可移入 Web Worker。形势分数取值 -1 至 1，仅为棋型启发式，界面明确标注“非胜率”。

## ADR-006：证书用纯 SVG 字符串生成，并强制先核验证据

**决定**：`buildCertificateSvg` 第一步调用 `verifyEvidence`，胜负、手数、摘要、双方地址取自核验结果而不是证据文件中的自述字段；所有文本经 `escapeXml`；不嵌入脚本、字体或外链。

**理由**：证书是“可展示的证据”，不能成为篡改入口。篡改棋谱或交换签名的证据在测试中都会使生成抛错。**边界**：证书不核对链上回执；非空棋谱证明签名在自述域中的有效性，不证明该域真实部署。交易、积分等文件自述明确标注为未核验，删除来自未签名 metrics 的节省比例，不能把图片当成链上结算证明。独立的证据导入/恢复流程会通过配置的 RPC 核验参与者、积分及回执。

## ADR-007：视觉改造只动展示层，用设计令牌 + 程序化审计约束

**决定**：样式拆为 tokens/base/layout/board/panels/pages/responsive 七个文件，所有颜色与字号来自令牌；保持既有可访问名称不变；新增 `scripts/audit-ui.mjs` 把“正文 ≥12px、对比度 ≥4.5:1、无横向溢出、控件有名称”写成断言。

**理由**：原样式是 8 行 33 KB，难以维护；“好看”不可测，但可访问性可测。审计在第一次运行就发现 12 项对比度问题（见 `bug-retrospective.md` B3），说明审计有实际价值。
